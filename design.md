# Migration Design — vobs/dw_source/isrpt/isbert/SQL/aktuell/aufbereitung/bin/r_ausd_bp_ta_bcp_msisdn.ksh

## 1. Purpose & Scope
This job, `r_ausd_bp_ta_bcp_msisdn.ksh`, is a KornShell script designed for the initial provisioning of selected basic products for BERT. Its primary purpose is to orchestrate the process of generating a cutoff-date extraction of contract cache data from the Data Warehouse (DWH) and making it available for Forderungsscoring. It handles command-line parameter parsing, defaults for the cutoff date, job logging, and basic error handling, ultimately delegating the core data processing to a separate kernel script, `k_ausd_bp_ta_bcp_msisdn.ksh`.

The script processes contract data based on a `Stichtag` (cutoff date) and an optional `Wiederanlaufwert` (restart value). If a restart value is provided, only contracts with `DWH_VERTRAG_ID` greater than this value are processed and written to the FOS table.

## 3. Target Architecture
The current KornShell script acts as an orchestration layer, handling parameter parsing, environment setup, logging, and invoking a primary kernel script. In the BigQuery ecosystem, this orchestration functionality is best re-implemented using **Google Cloud Composer (Airflow)**.

The target architecture will consist of:
*   **Airflow DAG:** A Python-based Airflow Directed Acyclic Graph (DAG) will replace the KornShell script. This DAG will handle:
    *   Parameter definition and parsing (e.g., via Airflow `dags.params` or custom operators).
    *   Dynamic date calculations (`Stichtag`).
    *   Restart logic (`Wiederanlaufwert`).
    *   Orchestration of subsequent tasks.
    *   Centralized logging and error handling, leveraging Airflow's built-in capabilities and potentially custom logging operators.
*   **BigQuery:** The core data processing logic currently within `k_ausd_bp_ta_bcp_msisdn.ksh` (and potentially any underlying SQL it executes) will be migrated to BigQuery. This could involve:
    *   **BigQuery SQL scripts:** For direct data transformations.
    *   **BigQuery Stored Procedures:** For encapsulating more complex, procedural SQL logic.
    *   **PySpark on Dataproc/Spark on GKE:** If the `k_ausd_bp_ta_bcp_msisdn.ksh` script involves significant non-SQL data manipulation or complex transformations better suited for a Spark environment.
*   **Google Cloud Storage (GCS):** For storing logs generated by the Airflow DAG and any intermediate data files if necessary.
*   **Python Helper Modules:** The functionality of the sourced shell helper scripts (e.g., `f_alis_msgerr.ksh`, `h_alis_parameter.ksh`, `h_alis_date.ksh`) will be re-implemented as Python functions or classes within Airflow operator modules or as standalone Python helper libraries.

The primary goal is to leverage Google Cloud's managed services for scalability, reliability, and maintainability.
