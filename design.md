# Migration Design — EXIS_SD_APT_BESTANDS

## 1. Purpose & Scope
The original UC4 job `DW.DWH_EXIS_SD_APT_BESTANDS` is responsible for exporting stock data. It reads data from source tables `SOF$TA_BPR_OPTIONEN`, `SOF$VI_L_OPTIONZUORDNUNG`, and `RPT$TA_S_D1_VERTRAG`, processes it using an external executable (`r_exis_v2`), and then writes the output to a compressed CSV file named `DWHM_APT_BESTANDSREPORT_<yyyymmddhhmmss>.csv.gz`. The job runs on a UNIX host `DWHDWH5P` with login `DW.UNIX.ISTNS`. The purpose of this migration is to re-platform this data export process to Google Cloud Platform, using BigQuery for data storage and Airflow for orchestration.

## 2. Source Inventory
The migration job is assembled from a single UC4 `JOBS_UNIX` object.

## 3. Target Architecture
The migrated job will be orchestrated by Airflow and run on Google Cloud Platform.
- **Orchestration**: Airflow DAG deployed on Cloud Composer.
- **Computation**: The shell script logic (specifically the `r_exis_v2` executable) will be re-implemented as a PySpark application. This PySpark job will be executed on a Dataproc cluster.
- **Data Storage**:
    - Source tables (`SOF$TA_BPR_OPTIONEN`, `SOF$VI_L_OPTIONZUORDNUNG`, `RPT$TA_S_D1_VERTRAG`) will be migrated to BigQuery tables.
    - The output CSV.GZ file (`DWHM_APT_BESTANDSREPORT_<yyyymmddhhmmss>.csv.gz`) will be stored in Google Cloud Storage (GCS) and potentially loaded into a BigQuery table if required for further downstream processing or analytics.

## 4. Data Flow & Lineage
The original UC4 job runs a shell script that performs data export.
1.  **Orchestration**: The Airflow DAG (`dw_dwh_exis_sd_apt_bestands`) triggers the data export process.
2.  **Data Extraction & Transformation**: A DataprocSubmitJobOperator will execute a PySpark script (migrated from `r_exis_v2` and its configuration) that connects to the BigQuery source tables (`SOF_TA_BPR_OPTIONEN`, `SOF_VI_L_OPTIONZUORDNUNG`, `RPT_TA_S_D1_VERTRAG`). It will extract, transform, and then write the processed stock data.
3.  **Data Loading**: The PySpark script will write the transformed data as a compressed CSV.GZ file to a specified GCS bucket path (e.g., `gs://YOUR_BUCKET_NAME/exports/DWHM_APT_BESTANDSREPORT_<yyyymmddhhmmss>.csv.gz`).

The execution order will be a single sequential task:
`start >> dwh_exis_sd_apt_bestands_task >> end`

## 5. Transformation Logic
The core transformation logic resides within the `r_exis_v2` executable and its configuration file `h_exis_apt_bestandsdaten.var`, currently invoked by the shell script. This logic needs to be fully reverse-engineered and re-implemented.

**Current Logic (Shell Script within UC4):**
```bash
:inc DW.HOLE_PFAD
:set &DWH_JOB_KENNUNG='EXIS_SD_APT_BESTANDS'
. $HOME/.dw_init

$HOME/aktuell/exporter/is/bin/r_exis_v2 -k $HOME/aktuell/exporter/apt/cfg/h_exis_apt_bestandsdaten.var

:inc DW.LESE_LOG
```
This indicates:
- Initialization steps (`DW.HOLE_PFAD`, `DWH_JOB_KENNUNG`, `.dw_init`). These will need to be mapped to Airflow variables or Dataproc job parameters.
- Execution of `r_exis_v2` with a key (`-k`) pointing to a configuration file. The functionality of `r_exis_v2` must be understood:
    - What are the exact SQL queries it executes against `SOF$TA_BPR_OPTIONEN`, `SOF$VI_L_OPTIONZUORDNUNG`, `RPT$TA_S_D1_VERTRAG`?
    - How does it join these tables?
    - What filtering, aggregation, or other transformations does it perform?
    - What is the schema of the output CSV?
    - How is the `DWHM_APT_BESTANDSREPORT_<yyyymmddhhmmss>.csv.gz` filename generated?

**Target Logic (PySpark):**
The `r_exis_v2` logic will be re-written as a PySpark application.
1.  **Read Data**: The PySpark application will read data from the corresponding BigQuery tables (e.g., `project.dataset.SOF_TA_BPR_OPTIONEN`).
2.  **Apply Transformations**: Implement the identified data extraction and transformation logic from `r_exis_v2` using Spark SQL or PySpark DataFrames.
3.  **Write Output**: Write the resulting DataFrame as a gzipped CSV file to a GCS location. The filename generation logic for `DWHM_APT_BESTANDSREPORT_<yyyymmddhhmmss>.csv.gz` will be replicated in PySpark.
