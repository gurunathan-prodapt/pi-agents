### Shell Script Analysis: Detailed Design Document

#### 1. Purpose and Data Flow
The KornShell script `k_exis_ftp2.ksh` is a generic data transfer utility designed to securely transfer an export file to a target FTP server. 

To ensure transactional safety and avoid downstream processes consuming incomplete files, the script implements a two-stage delivery mechanism:
1. **Upload as Temporary:** It transfers the source file (`p_Datei`) to the remote target directory with a `.tmp` suffix (`${p_Datei}.tmp`).
2. **Rename to Final:** Upon a verified, successful transfer, it renames the remote temporary file back to its original name on the destination system.

#### 2. Input Parameters
The script accepts eight positional parameters:
*   `$1` (`p_EintragsNr`): Logging entry/run identifier used for auditing.
*   `$2` (`p_Datei`): Source path/filename of the export file.
*   `$3` (`p_Server`): Destination FTP host name or IP address.
*   `$4` (`p_User`): FTP Username.
*   `$5` (`p_Passwort`): FTP Password.
*   `$6` (`p_Verzeichnis`): Target directory on the remote FTP server.
*   `$7` (`p_Endung`): Target file extension (reserved for configuration).
*   `$8` (`p_Debug`): Debug switch (integer flags; `1` for active logging).

#### 3. Dependencies and Infrastructure Calls
*   **Initialization Scripts:** Loads configuration variables and environment details (`~/.ccr_init`).
*   **Logging Wrapper:** Calls `h_alis_meldungen.ksh` (which defines standard log output functions like `CCRMSG_LogDebug`).
*   **FTP Wrappers:** Calls `h_alis_ftp.ksh` which contains low-level wrappers:
    *   `CCRFTP_Senden`: Sends a local file to a remote server using a temporary target name.
    *   `CCRFTP_Umbenennen`: Renames a file directly on the remote server.
*   **Exit Statuses:** Uses global application statuses `k_FehlerShell` (indicates script error/failure) and `k_FertigOK` (indicates successful execution).

#### 4. BigQuery Mapping Strategy
Since BigQuery is a serverless relational data warehouse, it does not possess native networking protocols (like FTP/SFTP) to push physical files directly to external systems. In a migrated enterprise architecture:
*   **File Transfer Externalization:** The raw FTP execution logic is migrated to a secure Cloud Function or a Google Cloud Workflows pipeline.
*   **Coordination Layer:** A BigQuery Stored Procedure orchestrates the run state, writes logging data to BigQuery audit tables, and communicates with the file transfer layer.
*   **Status Management:** Logging functions (`CCRMSG_LogDebug`) map to direct `INSERT` DML operations on an audit table (`ccr_audit_log`).
*   **Integration Interface:** The file transfer is triggered via an External Connection in BigQuery, calling a Cloud Function API (`cloud_function_ftp_transfer`).

### Assumptions and Additional Notes

1. **Audit Database Infrastructure:** We assume the existence of a database system containing an operational logging table named `project.dataset.ccr_audit_log` to persist trace records.
2. **Environment Constants:** Constants like `k_FehlerShell` and `k_FertigOK` are mapped to typical integer return codes (`1` for error, `0` for success).
3. **External FTP Adapter:** We assume a Google Cloud Function or equivalent API endpoint is registered inside BigQuery as an External Connection (`project.location.ftp_connection`). This endpoint accepts a JSON payload detailing the transfer job.
4. **Error Handling Strategy:** Standard SQL exception handling blocks (`BEGIN...EXCEPTION WHEN ERROR THEN...END`) are utilized to guarantee database consistency and return clear error diagnostic codes back to the parent workflow manager.

-- Main orchestration Stored Procedure representing the k_exis_ftp2.ksh script
CREATE OR REPLACE PROCEDURE `project.dataset.sp_exis_ftp2`(
  IN p_EintragsNr STRING,
  IN p_Datei STRING,
  IN p_Server STRING,
  IN p_User STRING,
  IN p_Passwort STRING,
  IN p_Verzeichnis STRING,
  IN p_Endung STRING,
  IN p_Debug INT64,
  OUT v_Error INT64
)
BEGIN
  -- Constant declarations mapping to shell constants
  DECLARE k_FehlerShell INT64 DEFAULT 1;
  DECLARE k_FertigOK INT64 DEFAULT 0;
  
  -- Local state trackers
  DECLARE v_TempDatei STRING;
  DECLARE v_Response JSON;
  DECLARE v_Status STRING;
  
  -- Generate temporary file name path with .tmp suffix
  SET v_TempDatei = CONCAT(p_Datei, '.tmp');
  SET v_Error = k_FertigOK;

  -- Debug Logging block
  IF p_Debug = 1 THEN
    -- Output to query console run results
    SELECT FORMAT("Uebertrage %s", p_Datei) AS debug_message;
    
    -- Insert record into Central Logging Table
    INSERT INTO `project.dataset.ccr_audit_log` (
      eintrags_nr, 
      log_timestamp, 
      severity, 
      message
    )
    VALUES (
      p_EintragsNr, 
      CURRENT_TIMESTAMP(), 
      'DEBUG', 
      CONCAT("Uebertrage ", p_Datei)
    );
  END IF;

  -- Phase 1: Upload source file to the remote target as a .tmp file (CCRFTP_Senden)
  BEGIN
    SET v_Response = `project.dataset.ext_ftp_transfer_handler`(
      p_Datei,
      v_TempDatei,
      p_Server,
      p_User,
      p_Passwort,
      p_Verzeichnis,
      'SEND'
    );
    
    -- Extract execution status from JSON response payload
    SET v_Status = JSON_VALUE(v_Response.status);
    
    IF v_Status != 'SUCCESS' THEN
      SET v_Error = k_FehlerShell;
    END IF;
    
  EXCEPTION WHEN ERROR THEN
    -- Fallback safety for unexpected network failures
    SET v_Error = k_FehlerShell;
  END;

  -- Verify Phase 1 transfer success
  IF v_Error != k_FertigOK THEN
    INSERT INTO `project.dataset.ccr_audit_log` (eintrags_nr, log_timestamp, severity, message)
    VALUES (p_EintragsNr, CURRENT_TIMESTAMP(), 'ERROR', CONCAT("Konnte ", p_Datei, " nicht uebertragen."));
    
    -- Return error status and exit procedure
    RETURN;
  END IF;

  -- Phase 2: Rename the .tmp file to its original target name (CCRFTP_Umbenennen)
  BEGIN
    SET v_Response = `project.dataset.ext_ftp_transfer_handler`(
      v_TempDatei,
      p_Datei,
      p_Server,
      p_User,
      p_Passwort,
      p_Verzeichnis,
      'RENAME'
    );
    
    -- Extract execution status from JSON response payload
    SET v_Status = JSON_VALUE(v_Response.status);
    
    IF v_Status != 'SUCCESS' THEN
      SET v_Error = k_FehlerShell;
    END IF;

  EXCEPTION WHEN ERROR THEN
    -- Fallback safety for unexpected network failures
    SET v_Error = k_FehlerShell;
  END;

  -- Verify Phase 2 rename success
  IF v_Error != k_FertigOK THEN
    INSERT INTO `project.dataset.ccr_audit_log` (eintrags_nr, log_timestamp, severity, message)
    VALUES (p_EintragsNr, CURRENT_TIMESTAMP(), 'ERROR', CONCAT("Konnte ", p_Datei, " nicht umbenennen."));
    
    RETURN;
  END IF;

  -- Log successful overall completion
  INSERT INTO `project.dataset.ccr_audit_log` (eintrags_nr, log_timestamp, severity, message)
  VALUES (p_EintragsNr, CURRENT_TIMESTAMP(), 'INFO', CONCAT("Transfer abgeschlossen fuer Datei: ", p_Datei));

END;

### Python Pseudocode

Below is the design pattern for the Cloud Function endpoint called by BigQuery's external function. This handles the actual network connections, file stream transfers, and remote renaming operations.

```python
import os
import json
import ftplib
from google.cloud import storage

def ftp_transfer_adapter(request):
    """
    HTTP Cloud Function designed to handle SFTP/FTP interactions.
    Accepts BigQuery External Connection JSON arrays.
    """
    try:
        request_json = request.get_json(silent=True)
        
        # BigQuery sends data wrapped inside a 'calls' list
        if not request_json or 'calls' not in request_json:
            return json.dumps({"replies": [{"status": "ERROR", "message": "Invalid request payload"}]}), 200
        
        replies = []
        
        for call in request_json['calls']:
            # Parse parameters passed from BigQuery procedure
            source_file_path = call[0]    # Local/Cloud storage URI or identifier
            target_file_path = call[1]    # Output name/temporary name
            ftp_server = call[2]
            ftp_user = call[3]
            ftp_password = call[4]
            ftp_directory = call[5]
            action_type = call[6]         # 'SEND' or 'RENAME'
            
            # Establish standard FTP Connection
            ftp = ftplib.FTP(ftp_server)
            ftp.login(user=ftp_user, passwd=ftp_password)
            
            if ftp_directory:
                ftp.cwd(ftp_directory)
            
            if action_type == 'SEND':
                # Parse GCS URI bucket and blob path details if applicable
                # e.g., gs://my-export-bucket/exports/data.csv
                bucket_name = source_file_path.replace("gs://", "").split("/")[0]
                blob_name = "/".join(source_file_path.replace("gs://", "").split("/")[1:])
                
                # Fetch stream from Cloud Storage Bucket
                gcs_client = storage.Client()
                bucket = gcs_client.bucket(bucket_name)
                blob = bucket.blob(blob_name)
                
                # Download stream and upload directly to FTP
                with blob.open("rb") as data_stream:
                    ftp.storbinary(f'STOR {target_file_path}', data_stream)
                
                replies.append({"status": "SUCCESS", "message": "File uploaded successfully as temp."})
                
            elif action_type == 'RENAME':
                # Rename remote files directly on target server
                # target_file_path (old/temp name) -> source_file_path (new/original name)
                ftp.rename(source_file_path, target_file_path)
                replies.append({"status": "SUCCESS", "message": "File renamed successfully."})
                
            else:
                replies.append({"status": "ERROR", "message": f"Unsupported action: {action_type}"})
                
            ftp.quit()
            
        return json.dumps({"replies": replies}), 200
        
    except Exception as e:
        # Return structured error back to BigQuery Exception handler
        return json.dumps({"replies": [{"status": "ERROR", "message": str(e)}]}), 200
```
