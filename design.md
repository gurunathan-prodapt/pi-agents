# Migration Design — DW.BERT_AUSD_BP_TA_BCP_MSISDN

## 1. Purpose & Scope
This job, originally orchestrated by a UC4 scheduler, is responsible for preparing "instantiierten Basisprodukte" (instantiated basic products) related to MSISDN data for the BERT process. The core functionality involves enriching contract and product data with MSISDN information and storing it in a staging table.

The scope of this migration is to re-platform the existing UC4 job, KornShell control scripts, and Oracle SQL transformation into a BigQuery-centric data pipeline orchestrated by Apache Airflow on Google Cloud Platform.

## 1. Purpose & Scope
The job `DW.BERT_AUSD_BP_TA_BCP_MSISDN` is a critical ETL process within the legacy data warehouse environment. Its primary purpose is to prepare and enrich "instantiated basic products" (Basisprodukte) with MSISDN (Mobile Station International Subscriber Directory Number) data for the BERT reporting and analysis system. This involves extracting data from source tables, performing transformations, and loading the processed data into a target staging table.

The scope of this migration is to re-platform this job from its current UC4-orchestrated, KornShell-driven, Oracle SQL-based execution to a fully managed Google Cloud Platform (GCP) environment. The target architecture will leverage Apache Airflow for orchestration and BigQuery for data storage and transformation, eliminating the dependency on legacy UC4, KornShell scripts, and Oracle Database.

## 3. Target Architecture

The target architecture will utilize Google Cloud Platform services for a fully managed and scalable data pipeline:

*   **Orchestration**: Apache Airflow running on Cloud Composer.
*   **Data Storage**: Google BigQuery for all transformed data and staging tables.
*   **Transformation**: BigQuery SQL for the core data transformation logic. Shell script functionalities (parameter parsing, date handling, error handling, logging) will be re-implemented using Python operators within Airflow DAGs.
*   **External System Integration**: Cloud Storage for staging data if needed, and BigQuery for any external data sources migrated to GCP.

The entire job will be represented as a single Airflow DAG: `dw_bert_ausd_bp_ta_bcp_msisdn`.

## 4. Data Flow & Lineage

The execution flow of the legacy job and its mapping to the target architecture is as follows:

1.  **UC4 Job (`DW.BERT_AUSD_BP_TA_BCP_MSISDN.xml`)**:
    *   **Legacy**: Triggers the execution of `r_ausd_bp_ta_bcp_msisdn.ksh` on a UNIX host (`DWHDWH2P`) using login `DW.UNIX.ISBERT`.
    *   **Target**: Replaced by an Apache Airflow DAG (`dw_bert_ausd_bp_ta_bcp_msisdn`). The DAG will contain a sequence of Python operators to replicate the shell script logic and a BigQuery operator for the SQL transformation.

2.  **KornShell Wrapper (`r_ausd_bp_ta_bcp_msisdn.ksh`)**:
    *   **Legacy**:
        *   Sources `.dw_init` for environment setup.
        *   Sources utility scripts: `f_alis_msgerr.ksh`, `h_alis_parameter.ksh`, `h_alis_date.ksh`.
        *   Parses command-line parameters `-s` (Stichtag) and `-l` (Wiederanlaufwert).
        *   Determines `p_stichtag` if not provided (defaulting to system date).
        *   Sets up logging and error handling using `DWMSG_ErmittleNr`, `DWMSG_Logdateiname`, `DWMSG_ErzeugeEintrag`.
        *   Invokes `k_ausd_bp_ta_bcp_msisdn.ksh` with all parsed parameters.
    *   **Target**: The logic will be implemented as a series of Python functions within the Airflow DAG.
        *   A Python operator will handle parameter parsing and validation.
        *   Environment setup (`.dw_init`) will be replaced by Airflow variables or connection configurations.
        *   Logging and error handling will leverage Airflow's native capabilities.
        *   This operator will prepare the parameters needed for the subsequent transformation step.

3.  **KornShell Control Script (`k_ausd_bp_ta_bcp_msisdn.ksh`)**:
    *   **Legacy**:
        *   Sources `.dw_init`, error concept (`f_alis_msgerr.ksh`), date helper (`h_alis_date.ksh`), parameter helper (`h_alis_parameter.ksh`), and SQL*Plus helper (`h_alis_sqlplus.ksh`).
        *   Validates parameters (`p_JobKennung`, `p_EintragsNr`, `p_Stichtag`).
        *   Calls `DWDate_Datum_Check` for date format validation.
        *   Sets `Name_SQLskript` to point to `d_ausd_bp_ta_bcp_msisdn.sql`.
        *   Executes the SQL script using `starteSQLSkript` function (which likely wraps `sqlplus`). This function passes parameters such as `p_EintragsNr`, `Name_SQLskript`, `p_JobKennung`, `p_Stichtag`, `tmpFile`, `BERT_DIR_ROOT`, `p_datum_heute`, `p_datum_gestern`.
        *   Logs record counts and sets job status (`DWMSG_SetzeStatusOK`).
    *   **Target**: This logic will also be converted to Python operators in Airflow.
        *   Parameter validation and date checks will be Python functions.
        *   The call to `starteSQLSkript` will be replaced by a `BigQueryExecuteQueryOperator` (or a `BigQueryInsertJobOperator`) that executes the converted BigQuery SQL. Parameters will be passed as Jinja templates to the BigQuery operator.
        *   Logging of record counts and job status will be integrated with Airflow's XComs and logging.

4.  **Oracle SQL Script (`d_ausd_bp_ta_bcp_msisdn.sql`)**:
    *   **Legacy**:
        *   Reads `MAX(m.timecreated)` from `isbert_schema.dwtk_meldungen` to derive `v_datum`.
        *   Executes `isbert_schema.DWPA_UTIL_SKRIPT.runstatement` to `TRUNCATE TABLE sof$ta_bcp_msisdn`.
        *   Inserts into `sof$ta_bcp_msisdn` by joining `sof$ta_bpr_bcp` (alias `bp`) and `sof$ta_rn_vertrag` (alias `rn`) on `bp.cntrct_id_ref = rn.cntrct_id`.
    *   **Target**: Converted to BigQuery SQL, executed by an Airflow `BigQueryExecuteQueryOperator`.
        *   **Source Tables**: `isbert_schema.dwtk_meldungen`, `sof.ta_bpr_bcp`, `sof.ta_rn_vertrag` (assuming migration to BigQuery datasets `isbert_schema` and `sof`).
        *   **Target Table**: `sof.ta_bcp_msisdn` (in BigQuery).

**Overall Data Flow:**
Legacy Oracle Tables (`isbert_schema.dwtk_meldungen`, `sof$ta_bpr_bcp`, `sof$ta_rn_vertrag`)
  ↓
Airflow (Python operators for orchestration, parameter handling, logging)
  ↓
BigQueryExecuteQueryOperator (executing converted SQL)
  ↓
BigQuery Tables (`sof.ta_bcp_msisdn`)

## 5. Transformation Logic

The core transformation logic resides in `d_ausd_bp_ta_bcp_msisdn.sql` and will be directly translated to BigQuery SQL.

**Original Oracle SQL:**
```sql
DEFINE v_carmen = "@pcrs1"

COLUMN s_datum new_value v_datum noprint
SELECT NVL(TO_CHAR(MAX(m.timecreated),'YYYYMMDD'),'19000101') AS s_datum
  FROM isbert_schema.dwtk_meldungen m
 WHERE m.job_kennung = 'BERT_DROP_TEMP_TABLE';

begin
 isbert_schema.DWPA_UTIL_SKRIPT.runstatement(0, 'TRUNCATE TABLE sof$ta_bcp_msisdn REUSE STORAGE');
 end;
/

INSERT INTO sof$ta_bcp_msisdn
(CNTRCT_ID,
  BPR_ID,
  CNTRCT_ID_REF,
  TN_TEL_MSISDN )
SELECT /*+ full(bp) parallel(bp,4) full(rn) parallel(rn,4) */
          distinct
          bp.cntrct_id,
          bp.bpr_id,
          bp.cntrct_id_ref,
          rn.tn_tel_msisdn
FROM      sof$ta_bpr_bcp  bp,
          sof$ta_rn_vertrag  rn
WHERE     bp.cntrct_id_ref = rn.cntrct_id
;

COMMIT;
```

**Converted BigQuery SQL (as per `hql_sql_to_bqsql_design`):**
```sql
-- Step00: variable definition equivalent
DECLARE v_carmen STRING DEFAULT '@pcrs1';
DECLARE v_datum STRING DEFAULT (
  SELECT COALESCE(FORMAT_TIMESTAMP('%Y%m%d', MAX(m.timecreated)), '19000101')
  FROM `isbert_schema.dwtk_meldungen` AS m
  WHERE m.job_kennung = 'BERT_DROP_TEMP_TABLE'
);

-- Step01: truncate target table
TRUNCATE TABLE `sof.ta_bcp_msisdn`;

-- Step11c: enrich data with MSISDN of BCP contract
INSERT INTO `sof.ta_bcp_msisdn`
  (CNTRCT_ID, BPR_ID, CNTRCT_ID_REF, TN_TEL_MSISDN)
SELECT DISTINCT
  bp.cntrct_id,
  bp.bpr_id,
  bp.cntrct_id_ref,
```

## 6. External Dependencies

The following external dependencies have been identified and their replacement strategy:

*   **Oracle Database**:
    *   **Dependency**: Source tables `sof$ta_bpr_bcp`, `sof$ta_rn_vertrag`, and metadata table `isbert_schema.dwtk_meldungen` are all hosted in an Oracle Database. The target table `sof$ta_bcp_msisdn` is also an Oracle table.
    *   **Replacement**: All relevant Oracle tables will be migrated to BigQuery. `sof$ta_bpr_bcp`, `sof$ta_rn_vertrag`, `isbert_schema.dwtk_meldungen` will become source tables in BigQuery. `sof$ta_bcp_msisdn` will become the target table in BigQuery. The connection string implied by `DEFINE v_carmen = "@pcrs1"` will be obsolete.

*   **UNIX Host (`DWHDWH2P`) and Login (`DW.UNIX.ISBERT`)**:
    *   **Dependency**: The KornShell scripts execute on a specific UNIX server using a dedicated login.
    *   **Replacement**: The execution environment will shift to Cloud Composer (Airflow) for orchestration. All shell script logic will be re-implemented in Python, eliminating the need for a UNIX host.

*   **UC4/Automic Scheduler**:
    *   **Dependency**: Provides job scheduling and workflow orchestration.
    *   **Replacement**: Apache Airflow on Cloud Composer will take over scheduling and orchestration duties.

*   **KornShell (ksh)**:
    *   **Dependency**: The control and wrapper scripts are written in KornShell, utilizing its syntax, parameter parsing, and utility sourcing.
    *   **Replacement**: All KornShell logic will be re-written in Python, integrated into the Airflow DAG.

## 7. Unresolved / Risks

*   **Migration of Utility Scripts**: The KornShell scripts source several utility scripts (e.g., `f_alis_msgerr.ksh`, `h_alis_date.ksh`, `h_alis_parameter.ksh`, `h_alis_sqlplus.ksh`). The exact content and functionalities of these scripts are not fully analyzed. They will need to be re-implemented in Python to ensure all equivalent logic (error handling, date operations, parameter handling) is retained within the Airflow DAG. This might represent a `B2` (semi_auto) or `B3` (manual) effort depending on complexity.
*   **Parameter Passing Mechanism**: The KornShell scripts pass several parameters to the SQL script. The conversion of `starteSQLSkript` to a `BigQueryExecuteQueryOperator` needs careful consideration to ensure all required parameters are passed correctly to the BigQuery SQL context, potentially using Airflow's Jinja templating.
*   **`v_datum` Derivation**: The original SQL derives `v_datum` from `isbert_schema.dwtk_meldungen`. This dependency on a metadata table must be carefully migrated to BigQuery, ensuring the `dwtk_meldungen` table (or its equivalent) is available and correctly populated.
*   **Transactionality/Error Handling**: The original `WHENEVER SQLERROR CONTINUE/EXIT FAILURE` and `begin...end;/` block for truncation within the SQL script, along with the KornShell's `trap` commands, provide specific error handling and transaction control. The Airflow implementation needs to replicate this robustness using Airflow's task-level retries and error handling mechanisms.
*   **Data Volume and Performance**: The Oracle SQL uses `/*+ full(bp) parallel(bp,4) full(rn) parallel(rn,4) */` hints, suggesting potentially large datasets and performance considerations. While BigQuery handles parallelism automatically, validating performance post-migration is crucial.
*   **Missing Lineage Details**: The `lineage_edges` query returned no explicit edges, requiring manual inference of execution flow from source code analysis. This increases the risk of missing subtle dependencies.
