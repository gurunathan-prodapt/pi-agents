# Migration Design Document: ausd_bp_ta_cntrct_evn

## 1. Executive Summary & Job Identification
* **Job Name:** `ausd_bp_ta_cntrct_evn`
* **Source Platform:** Oracle DWH (orchestrated via UC4/Automic and KornShell wrapper scripts)
* **Target Platform:** Google Cloud Platform (GCP) — BigQuery and Cloud Composer (Apache Airflow)
* **Job Purpose:** This job truncates and populates the contract EVN (Einzelverbindungsnachweis / detailed call record) table `sof$ta_cntrct_evn` by aggregating and pivoting event indicators from the base product event table `sof$ta_bpr_evn`.
* **Complexity Tier:** Medium
* **Automation Rate:** 0.65 (Targeted for fully automated generation using the design specified here)

---

## 2. Legacy Architecture Analysis
The legacy workload is organized across four distinct layers of abstraction:
1. **Orchestrator Layer (`DW.BERT_AUSD_BP_TA_CNTRCT_EVN.xml`):**
   * An Automic/UC4 UNIX job definitions file.
   * Invokes the wrapper script `r_ausd_bp_ta_cntrct_evn.ksh`.
   * Includes general environment initializations and standard logging setups (`DW.HOLE_PFAD` and `DW.BERT_LESE_LOG`).
2. **Wrapper Shell Layer (`r_ausd_bp_ta_cntrct_evn.ksh`):**
   * Acts as the entry point from UC4.
   * Parses parameters: `-s` (Stichtag/Reporting date) and `-l` (Wiederanlaufwert/Restart checkpoint contract ID).
   * Calculates fallbacks: if Stichtag is not specified, it defaults to the system's current date.
   * Instantiates the corporate logging framework (`DWMSG_ErmittleNr`, `DWMSG_Logdateiname`, `DWMSG_ErzeugeEintrag`) and establishes signal traps (`trap`).
   * Calls the core orchestrator script: `k_ausd_bp_ta_cntrct_evn.ksh`.
3. **Control Shell Layer (`k_ausd_bp_ta_cntrct_evn.ksh`):**
   * Conducts basic validation and formatting checks on parameters.
   * Employs utility functions (`gestern.ksh`) to extract yesterday's date if needed.
   * Executes the SQL script `d_ausd_bp_ta_cntrct_evn.sql` using an SQL\*Plus wrapper (`starteSQLSkript`).
4. **Data Transformation Layer (`d_ausd_bp_ta_cntrct_evn.sql`):**
   * An Oracle SQL\*Plus script.
   * Determines active reporting run metadata.
   * Executes a `TRUNCATE TABLE` on the target table `sof$ta_cntrct_evn` using a utility wrapper package (`isbert_schema.DWPA_UTIL_SKRIPT.runstatement`).
   * Performs an aggregation and pivot of base product IDs (`bpr_id`) to assign specific weight values into `sof$ta_cntrct_evn`.

## 3. Target BigQuery Architecture & Data Flow
In the target GCP architecture:
* **Orchestration:** Cloud Composer (Airflow DAG) replaces the UC4 configuration and Shell wrappers.
* **Execution:** A single Cloud Composer DAG executes a BigQuery SQL script that contains both the `TRUNCATE` and the consolidated aggregate `INSERT` statements.
* **Environment Variables:** Configuration properties such as project IDs, dataset names, and connection parameters will be managed as Airflow Variables or DAG params.

### Data Lineage Map

```
       │
       ▼ (Transformation / CASE WHEN Pivot Group-By)
[sof$ta_cntrct_evn] (Target Table - Truncate and Insert)
```

## 4. Detailed Transformation Logic & Mappings

### 4.1 Schema Mappings
Oracle object names containing special characters like `$` are normalized to standard BigQuery-compatible underscores (`_`).

| Oracle Object Name | BigQuery Object Name | Description |
| :--- | :--- | :--- |
| `sof$ta_bpr_evn` | `isbert_schema.sof_ta_bpr_evn` | Source Base Product Event Table |
| `sof$ta_cntrct_evn` | `isbert_schema.sof_ta_cntrct_evn` | Target Contract EVN Table |
| `isbert_schema.dwtk_meldungen` | `isbert_schema.dwtk_meldungen` | Metadata messages table (optional auditing) |

### 4.2 SQL Decodes & Transformations
The Oracle `DECODE` function is refactored into standard ANSI BigQuery SQL `CASE WHEN` syntax. The parallel execution hint `/*+ parallel(bpr,4) */` is deprecated since BigQuery handles query parallelization dynamically.

#### Oracle Source SQL snippet:
```sql
SELECT /*+ parallel(bpr,4) */
       cntrct_id,
       sum(decode(bpr_id,32,  1,
                         2839,10,
                         2506,2,
                         2840,20,
                         3055,3,
                         3056,30,
                         3821,4,
                         0
                  )) as evn
FROM     sof$ta_bpr_evn bpr
GROUP BY cntrct_id;
```

#### BigQuery Standard SQL equivalent:
```sql
SELECT
  cntrct_id,
  SUM(
    CASE bpr_id
      WHEN 32   THEN 1
      WHEN 2839 THEN 10
      WHEN 2506 THEN 2
      WHEN 2840 THEN 20
      WHEN 3055 THEN 3
      WHEN 3056 THEN 30
      WHEN 3821 THEN 4
      ELSE 0
    END
  ) AS evn
FROM
  `your_gcp_project.isbert_schema.sof_ta_bpr_evn` AS bpr
GROUP BY
  cntrct_id;
```

## 8. Risks, Assumptions, and Manual Verification Checklist

### 8.1 Risks & Mitigations
* **Table Schema Integrity**: In Oracle, `sof$ta_cntrct_evn` column names were `CNTRCT_ID` and `EVN`. Ensure BigQuery target schemas are provisioned with lower or identical casing configurations depending on enterprise-wide styling strategies.
* **Date Parsing Formats**: The legacy shell script explicitly parsed `DDMMYYYY` with `gestern.ksh`. Standardize date structures in BigQuery tables using native `DATE` formats instead of string representations where possible.
* **Volume Handling**: `sof$ta_bpr_evn` might be massive. While the Oracle code optimized queries utilizing hints like `/*+ parallel(bpr,4) */`, BigQuery execution natively optimizes scans. However, partition and cluster strategies (e.g. partition by write/ingestion date or cluster by `cntrct_id`) should be assessed.

### 8.2 Migration Verification Checklist
1. Validate schema equivalence of `sof_ta_bpr_evn` and `sof_ta_cntrct_evn` in target BigQuery environment.
2. Execute a dry-run test of the refactored BigQuery INSERT SQL statement to confirm cost and syntax validity.
3. Deploy the compiled DAG `dw_bert_ausd_bp_ta_cntrct_evn.py` to the Cloud Composer `/dags` folder.
4. Trigger the DAG manually from the Airflow UI using different payload dates to test exception handlers and fallback configurations.
5. Perform data reconciliation (row-count and sum totals of the generated `EVN` metrics) between Oracle legacy and target BigQuery tables to assert analytical precision.
