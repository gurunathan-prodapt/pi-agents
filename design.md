# Migration Design — vobs/dw_source/isrpt/isbert/SQL/aktuell/aufbereitung/bin/k_ausd_v_ta_disc_zusgf.ksh

## 1. Purpose & Scope
This document outlines the migration strategy for the ETL job identified by `run_id: 5af228f1-3847-4cc6-9310-ed82ed19407c` and `seed_name: vobs/dw_source/isrpt/isbert/SQL/aktuell/aufbereitung/bin/k_ausd_v_ta_disc_zusgf.ksh`. The job's primary purpose is to prepare and consolidate discount data into a target table, `sof$ta_disc_zusgf`. This involves reading discount information, processing it (including concatenating discount details), and then populating the target table. The job also includes environmental setup, parameter parsing, and basic error handling. The migration target platform is BigQuery.

## 2. Source Inventory

### 2.1. `vobs/dw_source/isrpt/isbert/SQL/aktuell/aufbereitung/bin/k_ausd_v_ta_disc_zusgf.ksh`
- **Technology**: KornShell Script
- **Complexity Tier**: Medium
- **Automation Bucket**: Semi-Automatic (B2)
- **Purpose**: Orchestrates the execution of the main SQL logic. It handles environment initialization, command-line parameter parsing (`-j` for Job ID, `-f` for Entry Number), and invocation of the `d_ausd_v_ta_disc_zusgf.sql` script. It includes error checking and logging using utility functions.
- **Key Functionality**:
    - Sourcing shell utility scripts for environment setup, error messaging, date handling, parameter parsing, and SQL*Plus interaction.
    - Parameter validation.
    - Execution of an Oracle SQL script via a `starteSQLSkript` function (details of this function are external to this file but imply SQL*Plus execution).
    - Capturing the number of processed records to a temporary file.

### 2.2. `vobs/dw_source/isrpt/isbert/SQL/aktuell/aufbereitung/sql/d_ausd_v_ta_disc_zusgf.sql`
- **Technology**: Oracle SQL / PL/SQL
- **Complexity Tier**: Medium (inherits from parent shell script analysis)
- **Automation Bucket**: Semi-Automatic (B2) (inherits from parent shell script analysis)
- **Purpose**: This script contains the core data transformation logic. It defines Oracle SQL types and a pipelined PL/SQL function to aggregate discount details and then uses this function to populate the `sof$ta_disc_zusgf` table.
- **Key Functionality**:
    - Determines a reference date (`v_datum`) from `isbert_schema.dwtk_meldungen`.
    - Defines Oracle `TYPE`s (`sof$ty_o_discount`, `sof$ty_t_discount`) and a PL/SQL `PACKAGE` (`sof$sp_discount_functions`) with a pipelined `concat_discounts` function to concatenate discount strings based on `cntrct_id` and `cntrct_obj_version`.
    - Truncates the target table `sof$ta_disc_zusgf` using a `DWPA_UTIL_SKRIPT.runstatement` call.
    - Populates `sof$ta_disc_zusgf` by joining distinct contract information from `sof$ta_discount` with the aggregated discount strings generated by the `concat_discounts` function.

## 3. Target Architecture
The migrated job will run on Google Cloud Platform, leveraging BigQuery for data processing and storage, and potentially Cloud Composer (Airflow) for orchestration.

- **Storage**: All source Oracle tables (`isbert_schema.dwtk_meldungen`, `sof$ta_discount`) and the target table (`sof$ta_disc_zusgf`) will be migrated to BigQuery datasets and tables.
- **Transformation**: The Oracle SQL/PLSQL logic will be converted to BigQuery Standard SQL. The pipelined function will be replaced by equivalent SQL aggregation constructs.
- **Orchestration**: The KornShell script's orchestration logic will be translated into a Cloud Composer (Airflow) DAG, defining the dependencies and execution flow of the BigQuery SQL transformations.

## 4. Data Flow & Lineage

The overall data flow is as follows:

1.  **Orchestration (KornShell -> Airflow DAG)**: The `k_ausd_v_ta_disc_zusgf.ksh` script's responsibilities will be handled by an Airflow DAG.
    *   **Environment Setup**: Global variables and utility functions sourced by the shell script will be managed within the Airflow environment or as separate Python functions/modules.
    *   **Parameter Passing**: `p_JobKennung` and `p_EintragsNr` will become Airflow DAG parameters or configuration values.
    *   **SQL Script Execution**: The BigQuery SQL equivalent of `d_ausd_v_ta_disc_zusgf.sql` will be executed as a BigQueryOperator task within the Airflow DAG.
    *   **Error Handling**: The `f_alis_msgerr.ksh` and `DWMSG_MeldeFehler` logic will be replaced by Airflow's native logging and alerting mechanisms.

2.  **SQL Transformation (Oracle SQL -> BigQuery SQL)**: The `d_ausd_v_ta_disc_zusgf.sql` script's logic will be directly translated to BigQuery SQL.
    *   **Source Tables**: `isbert_schema.dwtk_meldungen` and `sof$ta_discount` (migrated to BigQuery).
    *   **Transformation**: The core logic involves calculating a `v_datum` and then joining distinct entries from `sof$ta_discount` with aggregated discount strings.
    *   **Target Table**: `sof$ta_disc_zusgf` (migrated to BigQuery).

**Execution Order:**

1.  Airflow DAG starts.
2.  Airflow task to determine `v_datum` from `isbert_schema.dwtk_meldungen`.
3.  Airflow task to truncate `sof$ta_disc_zusgf`.
4.  Airflow task to execute the main BigQuery SQL `INSERT` statement, which performs the aggregations and joins to populate `sof$ta_disc_zusgf`.
5.  Airflow task for post-processing or logging the record count.

### 5.2. `d_ausd_v_ta_disc_zusgf.sql` to BigQuery SQL

The CM MCP tool provided the following BigQuery SQL conversion:

```sql
-- BigQuery equivalent

DECLARE v_datum STRING DEFAULT (
  SELECT COALESCE(FORMAT_DATE('%Y%m%d', DATE(MAX(m.timecreated))), '19000101')
  FROM `isbert_schema.dwtk_meldungen` m
  WHERE m.job_kennung = 'BERT_DROP_TEMP_TABLE'
);

-- Optional: truncate target table if needed (handled by Airflow task)
-- TRUNCATE TABLE `sof$ta_disc_zusgf`;

INSERT INTO `sof$ta_disc_zusgf`
  (cntrct_id, cntrct_obj_version, disc_vector_ty, rabatt_alle)
WITH dzg AS (\n  SELECT DISTINCT
    CAST(cntrct_id AS INT64) AS cntrct_id,
    CAST(cntrct_obj_version AS INT64) AS cntrct_obj_version,
    disc_vector_ty
  FROM `sof$ta_discount`
),
con AS (
  SELECT
    CAST(cntrct_id AS INT64) AS cntrct_id,
    CAST(cntrct_obj_version AS INT64) AS cntrct_obj_version,
    STRING_AGG(rabatt_text, ', ' ORDER BY rabatt_text) AS rabatt_alle
  FROM (\n    SELECT DISTINCT
      CAST(cntrct_id AS INT64) AS cntrct_id,
      CAST(cntrct_obj_version AS INT64) AS cntrct_obj_version,
      CONCAT(CAST(rabatt AS STRING), ' (', CAST(rabatthoehe AS STRING), '%)') AS rabatt_text
    FROM `sof$ta_discount`
  )
  GROUP BY cntrct_id, cntrct_obj_version
)
SELECT
  dzg.cntrct_id,
  dzg.cntrct_obj_version,
  dzg.disc_vector_ty,
  con.rabatt_alle
FROM dzg
LEFT JOIN con
  ON dzg.cntrct_id = con.cntrct_id
 AND dzg.cntrct_obj_version = con.cntrct_obj_version;
```
**Key Changes in SQL Conversion:**
-   Oracle `TYPE`s and `PACKAGE` with pipelined function are replaced by a combination of Common Table Expressions (CTEs) and `STRING_AGG` for concatenating discount texts.
-   Oracle `NVL` is replaced by BigQuery `COALESCE`.
-   Oracle `TO_CHAR(MAX(m.timecreated), 'YYYYMMDD')` is replaced by `FORMAT_DATE('%Y%m%d', DATE(MAX(m.timecreated)))`.
-   Oracle outer join syntax `(+)` is replaced by explicit `LEFT JOIN`.
-   Data types `NUMBER(10)` and `VARCHAR2` are mapped to `INT64` and `STRING` respectively in BigQuery.
-   Table names are quoted with backticks for BigQuery standard SQL.

## 6. External Dependencies

-   **`isbert_schema.dwtk_meldungen` (Oracle Table)**: This table is read to determine `v_datum`. It needs to be migrated to BigQuery.
-   **`sof$ta_discount` (Oracle Table)**: This is a primary input table for discount data. It needs to be migrated to BigQuery.
-   **`isbert_schema.DWPA_UTIL_SKRIPT.runstatement` (Oracle Package)**: Used for truncating the target table. In BigQuery, this will be a `TRUNCATE TABLE` statement executed as a separate Airflow task before the `INSERT`.
-   **`@pcrs1` (Carmen DB via DB-Link)**: Mentioned in SQL script comments (`DEFINE v_carmen = "@pcrs1"`). The current SQL does not seem to actively use this DB-Link for data retrieval for the main insert. If any `sof$ta_discount` or `isbert_schema.dwtk_meldungen` data originates from Carmen, then data replication/ingestion from Carmen to BigQuery needs to be established (e.g., CDC, batch export/import). Based on current lineage, `sof$ta_discount` and `isbert_schema.dwtk_meldungen` are considered local tables.
-   **`trace.sql.cfg`, `SPOOL` commands**: Oracle-specific tracing and spooling will be replaced by Airflow's native logging.

## 7. Unresolved / Risks

-   **Shell Script Utility Functions**: The exact implementation and dependencies of the sourced shell utility scripts (e.g., `f_alis_msgerr.ksh`, `h_alis_sqlplus.ksh`, `starteSQLSkript`) are not fully detailed. These will require manual analysis and reimplementation in Python for the Airflow DAG. This is a `semi_auto` (B2) item.
-   **Dynamic Table Name (from `VIA` in lineage)**: The lineage initially showed `WRITES_TABLE:VIA` for the SQL script, but upon code review, this appears to be a historical/commented-out `MERGE` statement. The current `INSERT` explicitly targets `sof$ta_disc_zusgf`. This indicates a potential for misinterpretation in automated lineage analysis if comments are not fully considered. This risk is resolved by manual review.
-   **Oracle `TABLE` in lineage**: Similarly, the `READS_TABLE:TABLE` in lineage was likely a generic placeholder. The actual `SELECT` statement in the SQL script references `sof$ta_discount`. This risk is resolved by manual review.
-   **Performance Optimization**: While the BigQuery SQL conversion provides a functional equivalent, BigQuery's columnar storage and execution model might offer further optimization opportunities beyond a direct translation. Performance testing and tuning will be required post-migration.
