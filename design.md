## 2. SYSTEM MIGRATION CONTEXT & ENVIRONMENT

The following sections supplement the core MCP conversion logic with system context, cross-file dependencies, environment configuration, and risks.

### 2.1 Lineage & Call Chain
- **Upstream Trigger**: This script is a control/orchestration wrapper. In the legacy environment, it is triggered by an enterprise scheduler (such as UC4/Automic) via a root script (referenced in comments as `r_ausd_bp_ta_rn_einzeln.ksh`).
- **Downstream Logic**:
  - Validates command parameters (`-j`, `-f`, `-s`, `-l`).
  - Calls `gestern.ksh` to retrieve business-date references (`p_datum_heute` and `p_datum_gestern`).
  - Executes the core SQL logic contained in `d_ausd_bp_ta_rn_einzeln.sql` (under `${BERT_DIR_ROOT}/aufbereitung/sql/`).
  - Stores intermediate execution logs or counts in `$DW_DIR_UTL/bert_k_ausd_bp_ta_rn_einzeln.tmp` and registers the job run in the system job table `PoolBasisprodukt` (currently commented out as a direct call, but required in the target solution).

### 2.2 External System Replacements
- **Legacy Filesystem Output**: The local file `$DW_DIR_UTL/bert_k_ausd_bp_ta_rn_einzeln.tmp` is replaced by an in-memory variable in BigQuery Scripting, or optionally exported to a Cloud Storage (GCS) logging bucket.
- **Utility Libraries (`h_alis_*.ksh`)**:
  - `f_alis_msgerr.ksh` (Error Handling) $\rightarrow$ Replaced by BigQuery `EXCEPTION` handling and standard Airflow alerting on failure.
  - `h_alis_date.ksh` (Date Check) $\rightarrow$ Replaced by native `SAFE.PARSE_DATE('%d%m%Y', p_Stichtag)`.
  - `h_alis_sqlplus.ksh` $\rightarrow$ Replaced by direct BigQuery API queries or standard `BigQueryInsertJobOperator` in Airflow.
  - `gestern.ksh` $\rightarrow$ Computed natively via SQL (`DATE_SUB(CURRENT_DATE(), INTERVAL 1 DAY)`) or injected via Airflow context macros (`{{ ds }}`).

- **SQL File Execution**: The file `d_ausd_bp_ta_rn_einzeln.sql` is a direct dependency. It must be migrated to standard BigQuery DML/DDL. If the SQL logic is inlineable, it should be encapsulated inside the main BigQuery stored procedure or placed in a dedicated task within the Airflow DAG.
