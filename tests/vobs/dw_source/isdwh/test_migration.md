## Test Case 1: End-to-End Output Parity (Legacy vs. Migrated)

### Purpose
To verify that the migrated PySpark job produces an output file in Google Cloud Storage (GCS) that is structurally and textually identical to the legacy output file generated by the Ab Initio graph, given the same source database state.

### Setup
1. **Legacy Environment**:
   * Populate the Oracle source table `DWH$TA_L_MAP_VT_CARM_DWH` with a controlled set of test records (including edge cases: duplicate `vertrags_id`s, null `dwh_vertrag_id`s, and large integers).
   * Run the legacy Ab Initio graph `BHB_CCM_PROC_WriteContractMapLookup.mp` to generate the legacy lookup file.
   * Download the generated legacy file (e.g., `ContractMapLookup_legacy.txt`).

2. **Migrated Environment**:
   * Sync the BigQuery table `dwh_ta_l_map_vt_carm_dwh` with the exact same test records.
   * Set the environment variables `GCP_PROJECT`, `GCS_BUCKET`, and `BQ_DATASET`.

### Action
1. Run the migrated PySpark script `BHB_CCM_PROC_WriteContractMapLookup.py` via Dataproc or locally using a test runner:
   ```bash
   python BHB_CCM_PROC_WriteContractMapLookup.py \
     --first_day 20260814 \
     --last_day_plus_1 20260815
   ```
2. Download the generated GCS file from `gs://{GCS_BUCKET}/ccm_proc/ContractMapLookup.txt`.
3. Execute the following validation script to compare the legacy and migrated output files.

```python
import pytest
from google.cloud import storage

def download_gcs_file(bucket_name, blob_name, local_path):
    client = storage.Client()
    bucket = client.bucket(bucket_name)
    blob = bucket.blob(blob_name)
    blob.download_to_filename(local_path)

def test_file_parity():
    legacy_file_path = "test_data/ContractMapLookup_legacy.txt"
    migrated_file_path = "test_data/ContractMapLookup_migrated.txt"
    
    # Download migrated file from GCS
    download_gcs_file(
        bucket_name="my-test-bucket", 
        blob_name="ccm_proc/ContractMapLookup.txt", 
        local_path=migrated_file_path
    )
    
    with open(legacy_file_path, "rb") as f_legacy, open(migrated_file_path, "rb") as f_migrated:
        legacy_content = f_legacy.read()
        migrated_content = f_migrated.read()
        
    # Assert exact binary equivalence (including \x01 delimiters and \n newlines)
    assert legacy_content == migrated_content, "Binary mismatch between legacy and migrated output files!"
```

### Pass/Fail Criterion
* **Pass**: The GCS output file matches the legacy output file byte-for-byte.
* **Fail**: Any difference in row count, sorting order, field values, delimiters (`\x01`), or line endings (`\n`) is detected.

## Test Case 2: Transformation Correctness (Sorting, Deduplication, and Null Handling)

### Purpose
To validate that the PySpark transformation logic correctly handles sorting (ascending by `vertrags_id`), deduplication (dropping duplicate `vertrags_id`s), and null handling (representing null `dwh_vertrag_id` as empty strings).

### Setup
Initialize a local Spark session and construct a mock input DataFrame containing:
* Out-of-order `vertrags_id` values.
* Duplicate `vertrags_id` values (to test deduplication).
* Null values in `dwh_vertrag_id`.

### Action
Run a PySpark unit test executing the core transformation logic.

```python
import pytest
from pyspark.sql import SparkSession
from pyspark.sql import functions as F
from pyspark.sql.types import StructType, StructField, LongType

@pytest.fixture(scope="module")
def spark():
    return SparkSession.builder \
        .master("local[1]") \
        .appName("Unit-Test-ContractMapLookup") \
        .getOrCreate()

def test_contract_map_transform(spark):
    # Define schema matching BigQuery source
    schema = StructType([
        StructField("vertrags_id", LongType(), False),
        StructField("dwh_vertrag_id", LongType(), True)
    ])
    
    # Input data: 
    # - Row 1 & 2: Duplicate vertrags_id (100). Row 2 should be dropped.
    # - Row 3: Out of order vertrags_id (50). Should be sorted first.
    # - Row 4: vertrags_id (200) with NULL dwh_vertrag_id.
    input_data = [
        (100, 10001),
        (100, 10002),
        (50, 50001),
        (200, None)
    ]
    
    df_source = spark.createDataFrame(input_data, schema=schema)
    
    # Execute the core transformation logic
    df_processed = df_source \
        .select("vertrags_id", "dwh_vertrag_id") \
        .orderBy(F.col("vertrags_id").asc()) \
        .dropDuplicates(["vertrags_id"])
    
    results = df_processed.collect()
    
    # Assertions
    # 1. Row count must be 3 (one duplicate dropped)
    assert len(results) == 3
    
    # 2. Sorting check: vertrags_id 50 must be first, then 100, then 200
    assert results[0]["vertrags_id"] == 50
    assert results[1]["vertrags_id"] == 100
    assert results[2]["vertrags_id"] == 200
    
    # 3. Null handling check: vertrags_id 200 must have None (null) for dwh_vertrag_id
    assert results[2]["dwh_vertrag_id"] is None
```

### Pass/Fail Criterion
* **Pass**: The Spark transformation successfully sorts the dataset, removes duplicate keys, and preserves null values without throwing exceptions.
* **Fail**: The output is unsorted, duplicates remain, or null values are incorrectly converted to default values (like `0`).

## Test Case 3: BigQuery Stored Procedure Execution & Metadata Side-Effects

### Purpose
To verify that the BigQuery stored procedure `SetzeLadedatumAbInitio` is successfully executed with the correct arguments and updates the target metadata table.

### Setup
1. Ensure the BigQuery stored procedure `SetzeLadedatumAbInitio` is deployed in the target dataset.
2. Record the state of the target metadata/loading table (e.g., `DWH_LOAD_TRACKING`) before running the test.

### Action
1. Execute the stored procedure call using the BigQuery Python client.
2. Query the metadata table to verify the update.

```python
import pytest
from google.cloud import bigquery

def test_stored_procedure_execution():
    client = bigquery.Client()
    project = client.project
    dataset = "ccm_proc_dataset"  # Replace with test dataset
    
    target_object_name = "ContractMapLookup.txt"
    first_day = "20260814"
    last_day_plus_1 = "20260815"
    
    # Call the stored procedure
    sp_query = f"CALL `{project}.{dataset}.SetzeLadedatumAbInitio`('{target_object_name}', '{first_day}', '{last_day_plus_1}')"
    query_job = client.query(sp_query)
    query_job.result()  # Wait for execution
    
    # Assert side-effects: Query the load tracking table to verify the update
    verification_query = f"""
        SELECT load_status, first_day, last_day_plus_1 
        FROM `{project}.{dataset}.DWH_LOAD_TRACKING`
        WHERE target_object = '{target_object_name}'
        ORDER BY update_timestamp DESC
        LIMIT 1
    """
    verify_job = client.query(verification_query)
    results = list(verify_job.result())
    
    assert len(results) == 1, "No load tracking record found for the target object."
    row = results[0]
    assert row["first_day"] == first_day, f"Expected first_day {first_day}, got {row['first_day']}"
    assert row["last_day_plus_1"] == last_day_plus_1, f"Expected last_day_plus_1 {last_day_plus_1}, got {row['last_day_plus_1']}"
```

### Pass/Fail Criterion
* **Pass**: The stored procedure executes without errors, and the tracking table reflects the correct `first_day` and `last_day_plus_1` values.
* **Fail**: The stored procedure execution fails, or the tracking table is not updated with the correct parameters.
