The following test plan aims to ensure behavioral equivalence, covering output parity, transformation correctness, external system replacements, and data quality.

## Migration Validation Test Plan: BERT_V_TA_DISC_ZUSGF

### Pre-requisites for all Tests:

*   **Test Environment Setup**: Dedicated test environments for both legacy Oracle and new Google Cloud (BigQuery, Composer).

*   **Execution Access**: Permissions to execute the legacy Oracle job (or its core PL/SQL script) and the migrated Airflow DAG.
*   **Data Extraction Tools**: Tools or scripts to extract data from both Oracle and BigQuery target tables for comparison (e.g., SQL clients, Python with database connectors).
*   **Test Data Generation**: Scripts or procedures to generate specific, controlled test datasets for various scenarios.

### General Comparison Strategy:

For each test case, the general approach will be:
1.  **Prepare Test Data**: Load the specified test data into both Oracle `sof$ta_discount` and BigQuery `sof_ta_discount`. Ensure `dwtk_meldungen` is also set up if `v_datum` is relevant.
2.  **Execute Legacy Job**: Run the legacy Oracle PL/SQL script (`d_ausd_v_ta_disc_zusgf.sql`) against a temporary Oracle target table (e.g., `SOF$TA_DISC_ZUSGF_TEST`).
3.  **Execute Migrated Job**: Run the Airflow DAG (`bert_v_ta_disc_zusgf_dag.py`) which will populate the BigQuery target table (`project_id.dataset_id.sof_ta_disc_zusgf_test`).
4.  **Extract & Compare**: Extract the results from both `SOF$TA_DISC_ZUSGF_TEST` (Oracle) and `sof_ta_disc_zusgf_test` (BigQuery). Perform a row-by-row, column-by-column comparison. A robust comparison involves sorting both datasets by primary keys (`cntrct_id`, `cntrct_obj_version`, `rabatt_alle` if multiple rows per contract) and then comparing.

### Test Case 1: Output Parity - Full Data Reconciliation (Happy Path)

*   **Purpose**: To verify that for a representative set of input data, the migrated job produces an identical output dataset to the legacy job, ensuring overall functional equivalence.
*   **Setup**:
    1.  Populate `sof$ta_discount` (Oracle) and `sof_ta_discount` (BigQuery) with a diverse dataset including:
        *   Contracts with few discounts (total length < 500).
        *   Contracts with many discounts (total length > 500, requiring splitting into multiple output rows).
        *   Contracts with discounts of varying lengths.
        *   Contracts with identical `rabatt` values.
        *   Contracts with `NULL` or empty `rabatt` values.
    2.  Ensure `dwtk_meldungen` in both environments contains data that allows `get_sysdate_equivalent_task` to return a `v_datum`.
    3.  Create temporary target tables: `SOF$TA_DISC_ZUSGF_TEST` in Oracle and `project_id.dataset_id.sof_ta_disc_zusgf_test` in BigQuery.
*   **Action**:
    1.  Execute the legacy Oracle PL/SQL script to populate `SOF$TA_DISC_ZUSGF_TEST`.
    2.  Execute the `bert_v_ta_disc_zusgf_dag.py` Airflow DAG, configured to write to `project_id.dataset_id.sof_ta_disc_zusgf_test`.
*   **Pass/Fail Criterion**:
    *   **Pass**: The number of rows in `SOF$TA_DISC_ZUSGF_TEST` is identical to `sof_ta_disc_zusgf_test`. A row-by-row comparison (after sorting by `cntrct_id`, `cntrct_obj_version`, `rabatt_alle`) shows no differences in `cntrct_id`, `cntrct_obj_version`, `rabatt_alle`, and `disc_vector_ty` columns.
    *   **Fail**: Any discrepancy in row counts or data content.

*   **Example Comparison (Conceptual Python/SQL)**:
    ```python
    import pandas as pd
    from google.cloud import bigquery
    import cx_Oracle # Assuming Oracle connection

    def compare_tables(oracle_table, bq_project, bq_dataset, bq_table):
        # 1. Extract from Oracle
        oracle_conn = cx_Oracle.connect("user/pass@host:port/service")
        oracle_query = f"SELECT cntrct_id, cntrct_obj_version, rabatt_alle, disc_vector_ty FROM {oracle_table} ORDER BY cntrct_id, cntrct_obj_version, rabatt_alle"
        df_oracle = pd.read_sql(oracle_query, oracle_conn)
        oracle_conn.close()

        # 2. Extract from BigQuery
        bq_client = bigquery.Client(project=bq_project)
        bq_query = f"SELECT cntrct_id, cntrct_obj_version, rabatt_alle, disc_vector_ty FROM `{bq_project}.{bq_dataset}.{bq_table}` ORDER BY cntrct_id, cntrct_obj_version, rabatt_alle"
        df_bq = bq_client.query(bq_query).to_dataframe()

        # 3. Compare
        if len(df_oracle) != len(df_bq):
            print(f"FAIL: Row count mismatch. Oracle: {len(df_oracle)}, BigQuery: {len(df_bq)}")
            return False

        # Ensure consistent types for comparison
        df_oracle = df_oracle.astype(str)
        df_bq = df_bq.astype(str)

        # Use pandas.testing.assert_frame_equal for robust comparison
        try:
            pd.testing.assert_frame_equal(df_oracle, df_bq, check_dtype=True, check_exact=True)
            print("PASS: Dataframes are identical.")
            return True
        except AssertionError as e:
            print(f"FAIL: Dataframe content mismatch: {e}")
            # Optionally, print differences
            diff = df_oracle.compare(df_bq)
            print("Differences found:\n", diff)
            return False
    ```

### Test Case 2: Transformation Correctness - 500-Character Limit (Single Split)

*   **Purpose**: To specifically test the `concat_discounts_logic`'s ability to correctly split a concatenated string into two output rows when the 500-character limit is exceeded exactly once.
*   **Setup**:
    1.  Populate `sof$ta_discount` (Oracle) and `sof_ta_discount` (BigQuery) with data for a single `(cntrct_id, cntrct_obj_version)` group.
    2.  The `rabatt` values for this group should be carefully crafted such that:
        *   The first few `rabatt` items concatenate to a string just under 500 characters (e.g., 490-495 chars).
        *   Adding the *next* `rabatt` item (plus `', '`) pushes the total length over 500 characters.
        *   Example: `rabatt_1` (490 chars), `rabatt_2` (20 chars). `rabatt_1` is output, then `rabatt_2` starts a new string.
    3.  Ensure `disc_vector_ty` is consistent within the group.
    4.  Use temporary target tables as in Test Case 1.
*   **Action**:
    1.  Execute the legacy Oracle PL/SQL script.
    2.  Execute the Airflow DAG.
*   **Pass/Fail Criterion**:
    *   **Pass**: For the tested `(cntrct_id, cntrct_obj_version)` group, both legacy and migrated jobs produce exactly two output rows. The `rabatt_alle` values in these two rows are identical between systems, and their lengths are `<= 500`. The `disc_vector_ty` values are also identical.
    *   **Fail**: Incorrect number of output rows, or `rabatt_alle` content/length mismatch.
