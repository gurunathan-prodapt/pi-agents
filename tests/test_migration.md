### Test Case 1: Parameter Validation - Missing Mandatory Parameters

*   **Purpose:** Verify that the migrated Airflow DAG correctly identifies and fails when mandatory parameters (`p_JobKennung`, `p_EintragsNr`, `p_Stichtag`) are missing, mirroring the legacy script's `pruefeParameterGesetzt` and `DWMSG_MeldeFehler` behavior.
*   **Setup:**
    *   Ensure the Airflow DAG `k_ausd_adressen_dag` is deployed to Cloud Composer.
*   **Action:**
    *   Trigger the `k_ausd_adressen_dag` via the Airflow UI or CLI, providing only `p_eintragsnr='1'` and `p_stichtag='20230101'`, omitting `p_jobkennung`.
    *   Trigger the `k_ausd_adressen_dag`, providing `p_jobkennung='JOB1'` and `p_stichtag='20230101'`, omitting `p_eintragsnr`.
    *   Trigger the `k_ausd_adressen_dag`, providing `p_jobkennung='JOB1'` and `p_eintragsnr='1'`, omitting `p_stichtag`.
*   **Pass/Fail Criterion:**
    *   **Pass:** For each triggered DAG run, the `parse_and_validate_parameters_task` fails, and the Airflow task logs contain an error message indicating the missing parameter (e.g., "Parameter 'Jobkennung' is not set."). The overall DAG run status is "failed".
    *   **Fail:** The DAG completes successfully, or fails for an unrelated reason, or the error message is incorrect.

*   **Pass/Fail Criterion:**
    *   **Pass:** For each final target table, a row-by-row, column-by-column comparison (ignoring order if not specified) shows identical data between the Oracle output (in the comparison table) and the BigQuery output.     -- This query identifies any differences between the BigQuery output and the Oracle output (loaded into a comparison table).
    -- It should return 0 rows for a successful comparison.
