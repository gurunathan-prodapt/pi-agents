The following migration validation tests are designed to prove the behavioral equivalence of the BigQuery Stored Procedure `project.dataset.ausd_bp_ta_bpr_basis_wrapper` to its legacy KornShell counterpart `r_ausd_bp_ta_bpr_basis.ksh`. The tests cover output parity, transformation correctness (parameter handling, defaulting, date derivation), external system interactions (calling the kernel procedure, logging to BigQuery table), and data quality/schema assertions.

For the purpose of these tests, we assume `project.dataset` refers to your specific BigQuery project and dataset, e.g., `my_project.my_dataset`.

---

## Test Setup Prerequisites

Before running any tests, ensure the following:

1.  **`job_log` table exists:**
    ```sql
    CREATE TABLE IF NOT EXISTS my_project.my_dataset.job_log (
        job_id STRING NOT NULL OPTIONS(description="Unique identifier for the job run, often a UUID."),
        job_name STRING NOT NULL OPTIONS(description="Name of the job being executed (e.g., wrapper or kernel procedure)."),
        entry_timestamp TIMESTAMP NOT NULL OPTIONS(description="Timestamp when this log entry was recorded."),
        log_level STRING NOT NULL OPTIONS(description="Severity of the log entry (e.g., 'INFO', 'WARNING', 'ERROR')."),
        message STRING OPTIONS(description="Detailed log message."),
        status STRING OPTIONS(description="Overall status of the job at this entry point (e.g., 'STARTED', 'RUNNING', 'COMPLETED', 'FAILED', 'FAILED_PARAM_VALIDATION')."),
        processing_date DATE OPTIONS(description="The 'Stichtag' (processing date) for which the job was run."),
        restart_value INT64 OPTIONS(description="The 'Wiederanlaufwert' (restart value) used for the job."),
        error_details STRING OPTIONS(description="Contains error message and stack trace if the job failed."),
        kernel_job_entry_nr INT64 OPTIONS(description="The DW_EintragsNr passed to the kernel script for tracking.")
    );
    ```

2.  **`k_ausd_bp_ta_bpr_basis` (Kernel Procedure) exists and is testable:**
    To effectively test the wrapper, the kernel procedure needs to be able to:
    *   Log its invocation and parameters to `job_log`.
    *   Optionally simulate a failure.

    **Temporary Test Version of Kernel Procedure:**
    Deploy this version of the kernel procedure for testing, then revert to the actual implementation after validation.

    ```sql
    CREATE OR REPLACE PROCEDURE my_project.my_dataset.k_ausd_bp_ta_bpr_basis(
        IN p_job_kennung STRING,
        IN p_stichtag STRING,
        IN p_dw_eintrags_nr INT64,
        IN p_wiederanlauf_wert INT64,
        IN p_simulate_failure BOOL DEFAULT FALSE
    )
    OPTIONS(
        description="Temporary test version of k_ausd_bp_ta_bpr_basis for migration validation."
    )
    BEGIN
        -- Log that the kernel procedure is executing
        INSERT INTO my_project.my_dataset.job_log (
            job_id, job_name, entry_timestamp, log_level, message, status, processing_date, restart_value, kernel_job_entry_nr
        ) VALUES (
            p_job_kennung, 'k_ausd_bp_ta_bpr_basis', CURRENT_TIMESTAMP(), 'INFO',
            'Kernel procedure received Stichtag: ' || p_stichtag || ', Wiederanlaufwert: ' || p_wiederanlauf_wert ||
            ', DW_EintragsNr: ' || CAST(p_dw_eintrags_nr AS STRING),
            'RUNNING_KERNEL', PARSE_DATE('%d%m%Y', p_stichtag), p_wiederanlauf_wert, p_dw_eintrags_nr
        );

        IF p_simulate_failure THEN
           SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Simulated error in kernel procedure!';
        END IF;

        -- Log successful completion
        INSERT INTO my_project.my_dataset.job_log (
            job_id, job_name, entry_timestamp, log_level, message, status, processing_date, restart_value, kernel_job_entry_nr
        ) VALUES (
            p_job_kennung, 'k_ausd_bp_ta_bpr_basis', CURRENT_TIMESTAMP(), 'INFO',
            'Kernel procedure completed successfully.',
            'COMPLETED_KERNEL', PARSE_DATE('%d%m%Y', p_stichtag), p_wiederanlauf_wert, p_dw_eintrags_nr
        );
    END;
    ```

3.  **`ausd_bp_ta_bpr_basis_wrapper` (Wrapper Procedure) exists:**
    Ensure the wrapper procedure is deployed as provided in the `GENERATED MIGRATION CODE` section.

### Test Case 1: Successful Execution with All Parameters Provided

*   **Purpose:** Verify the happy path where both `Stichtag` and `Wiederanlaufwert` are explicitly provided. This checks parameter passing, correct defaulting (or lack thereof), and full logging lifecycle.
*   **Setup:**
    1.  Clear the `my_project.my_dataset.job_log` table.
    2.  Ensure the test kernel procedure `k_ausd_bp_ta_bpr_basis` is set to *not* simulate failure (i.e., `p_simulate_failure` is `FALSE` or omitted).

    Execute the wrapper procedure with specific, valid parameters.

*   **Pass/Fail Criterion:**
    The `my_project.my_dataset.job_log` table must contain exactly 5 entries for this run, in the correct order, with the following characteristics:
    1.  **Wrapper STARTED:** `status = 'STARTED'`, `log_level = 'INFO'`, `processing_date = '2023-01-01'`, `restart_value = 12345`, `kernel_job_entry_nr = 1`.
    2.  **Wrapper RUNNING (calling kernel):** `status = 'RUNNING'`, `log_level = 'INFO'`, `processing_date = '2023-01-01'`, `restart_value = 12345`, `kernel_job_entry_nr = 1`.
    3.  **Kernel RUNNING:** `job_name = 'k_ausd_bp_ta_bpr_basis'`, `status = 'RUNNING_KERNEL'`, `log_level = 'INFO'`, `processing_date = '2023-01-01'`, `restart_value = 12345`, `kernel_job_entry_nr = 1`.
    4.  **Kernel COMPLETED:** `job_name = 'k_ausd_bp_ta_bpr_basis'`, `status = 'COMPLETED_KERNEL'`, `log_level = 'INFO'`, `processing_date = '2023-01-01'`, `restart_value = 12345`, `kernel_job_entry_nr = 1`.
    5.  **Wrapper COMPLETED:** `status = 'COMPLETED'`, `log_level = 'INFO'`, `processing_date = '2023-01-01'`, `restart_value = 12345`, `kernel_job_entry_nr = 1`.

### Test Case 3: Successful Execution with `p_stichtag_in` NULL/Empty (Defaulting to `CURRENT_DATE()`)

*   **Purpose:** Verify `p_stichtag` defaulting to the system date (`CURRENT_DATE()`) when not provided or empty.
*   **Setup:**
    1.  Clear the `my_project.my_dataset.job_log` table.
    2.  Ensure the test kernel procedure `k_ausd_bp_ta_bpr_basis` is set to *not* simulate failure.
*   **Action:**
    Execute the wrapper procedure without `p_stichtag_in` or with an empty string.
    ```sql
    -- Test with NULL
    CALL my_project.my_dataset.ausd_bp_ta_bpr_basis_wrapper(NULL, 54321);

    -- Test with empty string (after clearing log again)
    -- TRUNCATE my_project.my_dataset.job_log;
    -- CALL my_project.my_dataset.ausd_bp_ta_bpr_basis_wrapper('', 54321);
    ```
*   **Pass/Fail Criterion:**
    The `my_project.my_dataset.job_log` table must contain exactly 5 entries for this run.
    The `processing_date` in all entries must match `CURRENT_DATE()` in `DDMMYYYY` format (e.g., if run on 2023-10-27, `processing_date = '2023-10-27'`).
    The `restart_value` must be `54321`.
    The `job_id` and `kernel_job_entry_nr` should be consistent.

    ```sql
    -- Assertion SQL
    SELECT
    ```
