### Test Case 1: Output Parity - Full Data Comparison (Golden Record)

**Purpose:** To verify that the `ta_discount` table generated by the BigQuery Stored Procedure is identical to the `ta_discount` table generated by the legacy KornShell script, given the same input data. This is the most critical test for data correctness.

**Setup:**
1.  **Legacy Baseline:**
    *   Execute the legacy `k_ausd_v_ta_discount.ksh` script against a known, consistent set of source data in the Oracle database.
    *   Extract the resulting `ta_discount` table data from Oracle into a canonical format (e.g., sorted CSV, Parquet, or a temporary BigQuery table). Let's call this `legacy_ta_discount_golden`.

    `CALL my_project.my_dataset.r_ausd_vertrag_control('TEST_JOB_GOLDEN', 'ENTRY_GOLDEN');`

**Pass/Fail Criterion:**
The data in `my_project.my_dataset.ta_discount` must be exactly identical to the `legacy_ta_discount_golden` dataset. This includes row count, column values, and data types.

### Test Case 4: External System Replacements - Job Control Logic

**Purpose:** To verify that the BigQuery `job_control` and `job_log` tables correctly replace the legacy job management (ignoring active jobs, deactivating older jobs, registering status) and temporary file usage for record counts.

**Setup:**
1.  Ensure `my_project.my_dataset.job_control` and `my_project.my_dataset.job_log` are empty.
2.  Populate source tables (`cds_ta_discount_bc_assoc`, etc.) to allow for successful data processing and record counting.

**Action:**
1.  **Scenario A: First run (no active job).**
    *   Call `r_ausd_vertrag_control('JOB_CONTROL_TEST', 'ENTRY_1')`.
2.  **Scenario B: Second run with same `JobKennung` while first is still "active" (simulated).**
    *   Manually set the first job's `is_active` to `TRUE` and `status` to `RUNNING` in `job_control`.
    *   Call `r_ausd_vertrag_control('JOB_CONTROL_TEST', 'ENTRY_2')`.
3.  **Scenario C: Third run with same `JobKennung` after previous job completed.**
    *   Ensure previous job is `is_active = FALSE`.
    *   Call `r_ausd_vertrag_control('JOB_CONTROL_TEST', 'ENTRY_3')`.
4.  **Scenario D: Run with invalid parameters (e.g., missing `p_JobKennung`).**
    *   Call `r_ausd_vertrag_control(NULL, 'ENTRY_INVALID')`.

**Pass/Fail Criterion:**
*   **Scenario A:** One entry in `job_control` with `status = 'SUCCEEDED'`, `is_active = FALSE`, and `processed_records` matching the actual count. `job_log` should show start/end messages.

*   **Scenario C:** The *previous* job (from Scenario A) should be updated to `status = 'DEACTIVATED'`, `is_active = FALSE`. A new entry should be created for this run with `status = 'SUCCEEDED'`, `is_active = FALSE`, and correct `processed_records`.
*   **Scenario D:** `job_control` should have an entry with `status = 'FAILED'`, `is_active = FALSE`. `job_log` should contain an 'ERROR' message detailing the parameter validation failure. The procedure should raise an error.
