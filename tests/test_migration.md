As a senior data-migration QA engineer, I've designed a suite of validation tests for the migration of `k_ausd_v_ta_inv_def.ksh` to Google BigQuery. These tests aim to ensure behavioral equivalence, data integrity, and correctness of the migrated components.

The tests are organized by purpose and cover output parity, transformation logic, external system replacements (now BigQuery tables), and data quality assertions. Each test case includes its purpose, setup, action, and concrete pass/fail criteria. Python `pytest` and BigQuery SQL assertions are provided as runnable code examples.

**Assumptions for Test Code:**
*   A BigQuery client (`bq_client`) is initialized and authenticated.
*   `project_id` and `dataset_id` variables are configured for the target BigQuery environment.
*   Helper functions `_execute_bq_query`, `_get_table_data`, `_clear_table`, and `_insert_data` are available (examples provided in the first test case).
*   The `pytest.fixture(autouse=True)` `setup_teardown_tables` is used to ensure a clean state for target tables before each test.

## Test Case 2: Parameter Validation - Missing `p_JobKennung`

*   **Purpose:** To verify that the stored procedure correctly handles missing or empty `p_JobKennung` input parameters, raises an error, and logs the failure.
*   **Setup:** Ensure `my_gcp_project.isrpt_isbert.job_status_log` is empty.
*   **Action:**
    1.  Attempt to call `sp_k_ausd_v_ta_inv_def` with `p_JobKennung = NULL`.
    2.  Attempt to call `sp_k_ausd_v_ta_inv_def` with `p_JobKennung = ''` (empty string).
*   **Pass/Fail Criterion:**
    1.  Both calls must raise an error containing the message "FEHLER: Jobkennung parameter is missing or empty."
    2.  `my_gcp_project.isrpt_isbert.job_status_log` must contain two 'FAILED' entries.
    3.  For the `NULL` case, `job_kennung` in the log should be `NULL`. For the empty string case, `job_kennung` should be `''`.
    4.  The `message` field in both log entries must indicate the missing parameter.

*   **Test Code (Python/Pytest):**
    ```python
    def test_parameter_validation_missing_jobkennung():
        # Test with NULL JobKennung
        with pytest.raises(Exception, match="FEHLER: Jobkennung parameter is missing or empty."):
            _execute_bq_query(f"CALL `{project_id}.{dataset_id}.sp_k_ausd_v_ta_inv_def`(NULL, 'TEST_ENTRY_NR_2');")

        # Test with empty string JobKennung
        with pytest.raises(Exception, match="FEHLER: Jobkennung parameter is missing or empty."):
            _execute_bq_query(f"CALL `{project_id}.{dataset_id}.sp_k_ausd_v_ta_inv_def`('', 'TEST_ENTRY_NR_3');")

        job_log_entries = _get_table_data("job_status_log")
        assert len(job_log_entries) == 2

        # Check the first error log (NULL JobKennung)
        log_entry_null = next((e for e in job_log_entries if e["entry_number"] == "TEST_ENTRY_NR_2"), None)
        assert log_entry_null is not None
        assert log_entry_null["status"] == "FAILED"
        assert log_entry_null["job_kennung"] is None # BigQuery treats NULL as actual NULL
        assert "Jobkennung parameter is missing or empty" in log_entry_null["message"]

        # Check the second error log (empty string JobKennung)
        log_entry_empty = next((e for e in job_log_entries if e["entry_kennung"] == "TEST_ENTRY_NR_3"), None) # Corrected key
        assert log_entry_empty is not None
        assert log_entry_empty["status"] == "FAILED"
        assert log_entry_empty["job_kennung"] == ""
        assert "Jobkennung parameter is missing or empty" in log_entry_empty["message"]
    ```

## Test Case 4: Job Management - Ignore Active Job

*   **Purpose:** To verify that the job management logic correctly identifies and ignores new invocations if a job with the same `p_JobKennung` is already marked as 'RUNNING' in the `job_status_log`.
*   **Setup:**
    1.  Insert a 'RUNNING' entry into `my_gcp_project.isrpt_isbert.job_status_log` for `job_kennung = 'ACTIVE_JOB_KENNUNG'` with an arbitrary `entry_number`.
    2.  Ensure `my_gcp_project.isrpt_isbert.sof_ta_inv_def` is empty.
*   **Action:**
    *   Call `sp_k_ausd_v_ta_inv_def` with the same `job_kennung = 'ACTIVE_JOB_KENNUNG'` but a different `entry_number`.
        ```sql
        CALL `my_gcp_project.isrpt_isbert.sp_k_ausd_v_ta_inv_def`('ACTIVE_JOB_KENNUNG', 'NEW_ENTRY_NR');
        ```
*   **Pass/Fail Criterion:**
    1.  The procedure should complete without raising an error (it should return early as designed).
    2.  `my_gcp_project.isrpt_isbert.sof_ta_inv_def` must remain empty, indicating no data transformation occurred.
    3.  `my_gcp_project.isrpt_isbert.job_status_log` must contain two entries:
        *   The initial 'RUNNING' entry (status unchanged).
        *   A new 'IGNORED' entry for the latest invocation, with a message indicating that the job was ignored because another was running.

*   **Test Code (Python/Pytest):**
    ```python

        # Setup: Insert a 'RUNNING' entry for an existing job
        _insert_data("job_status_log", [
            {"job_name": "k_ausd_v_ta_inv_def", "job_kennung": "ACTIVE_JOB_KENNUNG",
             "entry_number": "OLD_ENTRY_NR", "status": "RUNNING",

        _clear_table("sof_ta_inv_def") # Ensure target table is empty

        # Action: Call the SP with the same JobKennung
        _execute_bq_query(f"CALL `{project_id}.{dataset_id}.sp_k_ausd_v_ta_inv_def`('ACTIVE_JOB_KENNUNG', 'NEW_ENTRY_NR');")

        # Assertions
        job_log_entries = _get_table_data("job_status_log")
        assert len(job_log_entries) == 2

        old_entry = next((e for e in job_log_entries if e["entry_number"] == "OLD_ENTRY_NR"), None)
        assert old_entry is not None
        assert old_entry["status"] == "RUNNING" # The old one should still be running
        assert old_entry["end_time"] is None # Should not have an end_time

        assert new_entry is not None
        assert new_entry["status"] == "IGNORED"
        assert "already running. Ignoring current invocation" in new_entry["message"]
        assert new_entry["start_time"] is not None
        assert new_entry["end_time"] is not None
        assert new_entry["end_time"] > new_entry["start_time"]

        # Verify no data was processed

        assert len(actual_sof_ta_inv_def) == 0
    ```
