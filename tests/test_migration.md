## Migration Validation Tests: DW.BERT_AUSD_V_TA_VERTRAG_TMP

### 1. Output Parity Tests

These tests focus on comparing the final output of the migrated job with the legacy job, ensuring identical results given identical inputs.

#### Test Case 1.1: Full Data Parity (End-to-End)

*   **Purpose:** To verify that the entire dataset generated by the migrated BigQuery job is identical to the dataset generated by the legacy Oracle job. This is the most critical test for behavioral equivalence.
*   **Setup:**
    1.  Ensure a snapshot of all Oracle source tables (as listed in the design document, e.g., `sof$ta_cntrct_crs3`, `sof$ta_bp_ref`, etc.) is ingested into the BigQuery `bert_source` dataset. This snapshot must be identical to the data present in Oracle at the time the legacy job was last successfully run for comparison.
    2.  Record the `v_datum` value used by the legacy job for the comparison run.
    3.  Execute the legacy `DW.BERT_AUSD_V_TA_VERTRAG_TMP` job in the Oracle environment and extract its final output from `sof$ta_vertrag_tmp` into a reference file (e.g., CSV, Parquet) or a dedicated comparison table in BigQuery (`bert_validation.ta_vertrag_tmp_legacy`).
    4.  Execute the migrated `dw_bert_ausd_v_ta_vertrag_tmp` Airflow DAG, ensuring the `initialize_job_parameters` task uses the *same* `v_datum` value as the legacy run (or manually override if necessary for exact comparison).
*   **Action:**
    1.  Run the Airflow DAG `dw_bert_ausd_v_ta_vertrag_tmp`.
    2.  After successful completion, compare the contents of `bert_staging.ta_vertrag_tmp` with the `bert_validation.ta_vertrag_tmp_legacy` table.
*   **Pass/Fail Criterion:**
    *   **Pass:** The number of rows in `bert_staging.ta_vertrag_tmp` is identical to `bert_validation.ta_vertrag_tmp_legacy`, and a full row-by-row, column-by-column comparison (ignoring column order if necessary) reveals no differences.
    *   **Fail:** Any discrepancy in row counts or data values between the two tables.

