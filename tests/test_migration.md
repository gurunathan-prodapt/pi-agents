The migration of `h_alis_parser.ksh` to a Python `AlisParser` class represents a significant re-engineering effort, moving from a shell-scripting paradigm with dynamic `eval` and external Unix utilities to a structured Python application. The tests below aim to ensure that this re-engineered solution is behaviorally equivalent to the legacy script, focusing on output parity and correct transformation logic.

Given the "retire" migration bucket and the complexity of the original script, it's crucial to validate that the Python implementation accurately replicates the intended text processing and templating behavior.

**Assumptions for Testing:**
*   The legacy `h_alis_parser.ksh` script is available and executable in a Unix-like environment for generating "golden" outputs.
*   The Python `AlisParser` class is the re-engineered component under test.
*   The Python `parse_template` method is the primary entry point for the re-engineered functionality, encompassing the logic previously distributed across `parser`, `parser_fillist`, `parser_filattrib`, and the orchestration of `parser_filfile`/`parser_filmeta`.
*   For `TIMESTAMP` tests, we will mock `datetime.datetime.now()` in Python to a fixed point in time to achieve deterministic output. For legacy KSH, one would typically set the system date or mock the `date` command for exact parity. For these tests, we'll assume a fixed reference date for comparison.
*   The complex list range expansion logic (`<LIST NAME M/S START-END>`) found in the KSH `parser` function is **not** implemented in the provided Python `AlisParser`. The Python code focuses on iterating through all items defined in a `LISTDEF` block and applying `<FIRST>`, `<MIDDLE>`, `<END>`, `<SINGLE>` based on item position. This is a known behavioral difference that would require further re-engineering if full parity for that specific feature is required. The tests below will focus on the features implemented in the Python code.

def test_custom_file_resolver():
    # Simulate a file resolver that fetches content from a "remote" source
    remote_files = {
        "gs://my-bucket/templates/header.txt": "Header content. Project: <PROJECT_NAME>",
        "gs://my-bucket/templates/footer.txt": "Footer content. Generated at: <TIMESTAMP FORMAT='%Y'/>"
    }

    def custom_gcs_resolver(filepath):
        if filepath in remote_files:
            return remote_files[filepath]
        raise FileNotFoundError(f"Simulated GCS file not found: {filepath}")

    parser_instance = AlisParser(file_resolver=custom_gcs_resolver)

    template_content = """
<PROJECT_NAME=MyAwesomeProject>
<INCLUDE FILE='gs://my-bucket/templates/header.txt'/>
Main body.

Footer content. Generated at: 2024
""".strip()

    with patch('datetime.datetime') as mock_datetime:
        mock_datetime.now.return_value = fixed_now
        mock_datetime.side_effect = lambda *args, **kw: datetime.datetime(*args, **kw)
        python_output = parser_instance.parse_template(template_content).strip()

    assert python_output == expected_output
    assert not parser_instance.errors
