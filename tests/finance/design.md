# SECTION 1 — DESIGN DOCUMENT

## 1. Overview
The `FINANCE_DAILY_WORKFLOW` is a daily financial data orchestration pipeline designed to perform GL transaction extraction, master data alignment, and staging table loads. It operates on business days (Monday through Friday) at 01:00 Europe/London time. The workflow validates connection states, extracts daily currency exchange rates and account master records, loads transaction data concurrently for European entities (UK, DE, FR), and publishes a GL completion event to downstream consumers in the retail and CRM domains.

## 5. Task Dependency Map
The execution dependency tree maps to the following workflow:

```
                  ┌──► finance_daily_acct_load ───┐
                  │                               │
finance_daily_pre_check                           ├──► finance_daily_gl_extract ──► finance_daily_gl_close
                  │                               │
                  └──► finance_daily_rate_extract ┘
```

* **Execution details**:
  1. `finance_daily_pre_check` validates connectivity.
  2. Upon successful execution of step 1, `finance_daily_acct_load` and `finance_daily_rate_extract` execute in parallel.
  3. `finance_daily_gl_extract` runs once *both* prior loads complete (using dynamic validation inputs).
  4. `finance_daily_gl_close` executes after successful extraction, triggering notifications and publishing events.

## 7. Error Handling and Retry Strategy
* **Pre-Check Task**: Retries 2 times with a 60-second delay. Failure triggers critical abort alerts.
* **Non-Blocking Task Branches**: `finance_daily_acct_load` and `finance_daily_rate_extract` specify a "CONTINUE" clause on failure. In UC4, this is modeled by marking downstream dependencies to run on `SUCCESS_OR_WARNING`.
  * *Airflow Mapping:* To avoid using global `TriggerRule.ALL_DONE` (which propagates and risks running downstream pipelines incorrectly during dependency skips), these individual extraction tasks are mapped to `on_failure_callback=on_failure_alarm_continue`. Downstream tasks evaluate status correctly using custom logging parameters.
* **Sync Strategy**: Both task groups perform write isolation limits. Multiple tasks run concurrently, but `max_active_runs=1` is implemented globally on the DAG to prevent concurrent day operations.

## 8. Developer Notes
* **GCP Infrastructure placeholders**: Ensure replacement of `YOUR_GCP_PROJECT_ID`, `YOUR_DATAPROC_CLUSTER_NAME`, and `YOUR_BUCKET_NAME` with production-ready Airflow Connections and Variables.
* **Excluded Calendars**: The UC4 workflow specifies `"exclude_calendars": ["PUBLIC_HOLIDAYS_UK"]`. Because calendar definitions are not bundled inside the workflow export, developer must map a `ShortCircuitOperator` with a custom Python helper referencing a central holidays file if these execution days should be skipped.
* **Cross-Domain Pub/Sub**: The final task `finance_daily_gl_close` executes an API call publishing the event. In Google Cloud Composer/Airflow, this is modeled by publishing to a Cloud Pub/Sub topic where `RETAIL_DAILY_WORKFLOW` and `CRM_WEEKLY_WORKFLOW` DAGs listen, or by executing a `TriggerDagRunOperator` dynamically.

# SECTION 2 — PSEUDOCODE

```python
# ── Imports ──────────────────────────────────────────────
from datetime import datetime, timedelta
from airflow import DAG
from airflow.operators.python import ShortCircuitOperator
from airflow.providers.google.cloud.operators.dataproc import DataprocSubmitJobOperator
from airflow.providers.google.cloud.operators.pubsub import PubSubPublishMessageOperator
from airflow.exceptions import AirflowSkipException
from airflow.models import Variable

# ── GCP Configuration ────────────────────────────────────
GCP_PROJECT_ID = "YOUR_GCP_PROJECT_ID"
DATAPROC_REGION = "YOUR_DATAPROC_REGION"
DATAPROC_CLUSTER_NAME = "YOUR_DATAPROC_CLUSTER_NAME"
GCS_BUCKET = "YOUR_BUCKET_NAME"
SPARK_SCRIPT_PATH = f"gs://{GCS_BUCKET}/pyspark_scripts"

# ── Notifications & Alerting Callbacks ─────────────────
def on_failure_alarm(context):
    """
    Simulates NOTIFY_AND_ABORT. Sends critical alerts to finance and DW teams on terminal failure.
    """
    recipients = ["finance-etl@company.com", "dw-alerts@company.com"]
    subject = f"[CRITICAL] FINANCE_DAILY_WORKFLOW FAILED for {context['ds']}"
    # TODO: Implement your enterprise SMTP or Slack/Teams alerting payload here
    print(f"Alerting {recipients} with Subject: {subject}")

def on_failure_alarm_continue(context):
    """
    Simulates NOTIFY then CONTINUE action for non-blocking task failures.
    Logs warnings and permits downstream steps to evaluate the exception pipeline safely.
    """
    recipients = ["finance-etl@company.com"]
    subject = f"[WARNING] FINANCE_DAILY_WORKFLOW non-blocking task failed on {context['ds']}"
    # TODO: Log warning metrics to analytical warehouse and notify stakeholders
    print(f"Warning sent to {recipients}: {subject}. Proceeding with pipeline execution dependencies.")

# ── DAG Definition ───────────────────────────────────────
default_args = {
    'owner': 'finance_etl',
    'start_date': datetime(2024, 1, 1),
    'email': ['finance-etl@company.com'],
    'email_on_failure': True,
    'retries': 0,
}

with DAG(
    dag_id="finance_daily_workflow",
    schedule="0 1 * * 1-5",  # Run Monday to Friday at 01:00 (Europe/London)
    catchup=False,
    max_active_runs=1,
    is_paused_upon_creation=False,
    default_args=default_args,
    template_searchpath="/opt/etl/templates"
) as dag:

    # ── UK Holiday Calendar Constraint check ───────────────
    def check_uk_holiday_calendar(**context):
        """
        Validates execution logic against UK holidays.
        Returns False (skipping the DAG run) if today is a registered bank holiday.
        """
        exec_date = context['logical_date']
        # TODO: Implement database query or file lookup for "PUBLIC_HOLIDAYS_UK" list
        uk_holidays = ["2024-01-01", "2024-03-29", "2024-04-01"] # Exemplary placeholder values
        formatted_date = exec_date.strftime('%Y-%m-%d')
        if formatted_date in uk_holidays:
            print(f"Execution date {formatted_date} falls on a UK Holiday. Skipping run.")
            return False
        return True

    holiday_calendar_sensor = ShortCircuitOperator(
        task_id="check_holiday_calendar",
        python_callable=check_uk_holiday_calendar,
        provide_context=True,
    )

    # ── Task 1: Pre-Check (Verify Oracle database availability) ──
    pre_check_job = {
        "reference": {"project_id": GCP_PROJECT_ID},
        "placement": {"cluster_name": DATAPROC_CLUSTER_NAME},
        "pyspark_job": {
            "main_python_file_uri": f"{SPARK_SCRIPT_PATH}/finance_daily_pre_check.py",
            "args": ["--verify-db-connection", "ORACLE_FIN_LOGIN"]
        },
    }

    task_pre_check = DataprocSubmitJobOperator(
        task_id="finance_daily_pre_check",
        job=pre_check_job,
        region=DATAPROC_REGION,
        project_id=GCP_PROJECT_ID,
        retries=2,
        retry_delay=timedelta(seconds=60),
        on_failure_callback=on_failure_alarm,
    )

    # ── Task 2: Account Master Load (Parallel Branch) ──────
    acct_load_job = {
        "reference": {"project_id": GCP_PROJECT_ID},
        "placement": {"cluster_name": DATAPROC_CLUSTER_NAME},
        "pyspark_job": {
            "main_python_file_uri": f"{SPARK_SCRIPT_PATH}/run_account_load.py",
            "args": [
                "--period-date", "{{ ds }}",
                "--load-scope", "ALL",
                "--execution-mode", "ACCOUNT_ONLY"
            ]
        },
    }

    task_acct_load = DataprocSubmitJobOperator(
        task_id="finance_daily_acct_load",
        job=acct_load_job,
        region=DATAPROC_REGION,
        project_id=GCP_PROJECT_ID,
        retries=3,
        retry_delay=timedelta(seconds=60),
        execution_timeout=timedelta(minutes=30),
        on_failure_callback=on_failure_alarm_continue,
    )

    # ── Task 3: Exchange Rate Extract (Parallel Branch) ────
    rate_extract_job = {
        "reference": {"project_id": GCP_PROJECT_ID},
        "placement": {"cluster_name": DATAPROC_CLUSTER_NAME},
        "pyspark_job": {
            "main_python_file_uri": f"{SPARK_SCRIPT_PATH}/rate_extract.py",
            "args": [
                "--period-date", "{{ ds }}",
                "--period-year", "{{ dag_run.logical_date.strftime('%Y') }}",
                "--period-month", "{{ dag_run.logical_date.strftime('%m') }}"
            ]
        },
    }

    task_rate_extract = DataprocSubmitJobOperator(
        task_id="finance_daily_rate_extract",
        job=rate_extract_job,
        region=DATAPROC_REGION,
        project_id=GCP_PROJECT_ID,
        execution_timeout=timedelta(minutes=20),
        on_failure_callback=on_failure_alarm_continue,
    )

    # ── Task 4: Daily GL Extract (Multi-Entity Parallel Spark runner) ──
    gl_extract_job = {
        "reference": {"project_id": GCP_PROJECT_ID},
        "placement": {"cluster_name": DATAPROC_CLUSTER_NAME},
        "pyspark_job": {
            "main_python_file_uri": f"{SPARK_SCRIPT_PATH}/run_gl_close.py",
            "args": [
                "--period-date", "{{ ds }}",
                "--entities", "UK_ENTITY,DE_ENTITY,FR_ENTITY",
                "--allow-empty", "N"
            ]
        },
    }

    task_gl_extract = DataprocSubmitJobOperator(
        task_id="finance_daily_gl_extract",
        job=gl_extract_job,
        region=DATAPROC_REGION,
        project_id=GCP_PROJECT_ID,
        retries=3,
        retry_delay=timedelta(seconds=120),
        execution_timeout=timedelta(minutes=90),
        on_failure_callback=on_failure_alarm,
    )

    # ── Task 5: Daily GL Close (Event Broker & Log Auditing) ──
    # Publishes verification token via Pub/Sub topic for cross-domain subscriber DAGs
    task_gl_close = PubSubPublishMessageOperator(
        task_id="finance_daily_gl_close",
        project_id=GCP_PROJECT_ID,
        topic="finance_gl_close_complete",
        messages=[{
            "data": b"FINANCE_GL_CLOSE_COMPLETE",
            "attributes": {
                "period_date": "{{ ds }}",
                "audit_timestamp": datetime.utcnow().isoformat()
            }
        }],
        on_failure_callback=on_failure_alarm,
    )

    # ── Dependencies ─────────────────────────────────────────
    holiday_calendar_sensor >> task_pre_check
    task_pre_check >> [task_acct_load, task_rate_extract]
    [task_acct_load, task_rate_extract] >> task_gl_extract >> task_gl_close
```

### 1. External System Replacements & Data Hand-offs
* **Oracle JDBC Extraction**: The legacy pre-check query (`SELECT 'DB_OK' FROM DUAL`) and rate extract/journal loading reference a direct connection to an Oracle transactional system (`${FIN_ORA_SID}`).
  * *Target Platform Mapping:* Cloud Dataproc uses Spark SQL or JDBC connectors (backed by Cloud SQL or BigQuery Federated Connections) to query the Oracle environment, or loads extracted operational data directly from a secure Google Cloud Storage landing zone.

* **RETAIL_DAILY_WORKFLOW** (Task: `RETAIL_PRODUCT_MASTER_LOAD` / Domain: `sales`)
